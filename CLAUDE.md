## 3. Design direction (non-negotiable)

**Reference points:** Stripe, Linear, Notion — clean, confident, editorial, lots of air.

- **Tone:** authoritative, credible, sophisticated; not sterile or overly corporate.
- **Palette:** warm paper neutrals plus one accent. Ink `#1f1b16`, cyan `#0088b0` (small text and focus use `#006786`). Magenta is not used. No process yellow.
- **Typography:** Instrument Sans for the interface, Newsreader for headlines, both via `next/font`. Weights 400 and 500. The wordmark is the name in the sans, with no italic.
- **Layout:** generous white space, 12-column grid, max content width 1440px, mobile-first.
- **Motion:** subtle only (fade/slide on scroll, hover states). Respect `prefers-reduced-motion`.
- **Imagery:** real guest headshots and episode thumbnails from YouTube; avoid stock photos.
- **Dark mode:** light only (warm paper, no dark surfaces). Tokens still live in one `:root` block so a later theme can be added without hunting through components.
- **Accessibility:** WCAG 2.1 AA — contrast, keyboard navigation, focus rings, alt text, semantic HTML.

Before building pages, load the `frontend-design` guidance if available and produce a small design-system page (`/styleguide`, dev-only) showing tokens, type scale, buttons, cards, and forms.

## 5. Site map (six public pages + admin)

### 5.1 Home `/`
- Hero: show name, one-line positioning ("Real implementation stories from the people who ship"), primary CTA → latest episode, secondary CTA → Be a Guest.
- Latest episode feature (YouTube embed or thumbnail with lite-embed).
- Recent episodes grid (3–6 cards).
- Featured guests strip (headshots, name, title, company).
- "Why this show" — 3 short value props (practitioner voice, real implementation, no theory).
- YouTube subscribe CTA.
- Minimal footer: nav, social links, contact email.

### 5.2 Episodes `/episodes` and `/episodes/[slug]`
- Listing: grid/list toggle, search, filter by topic/tag and guest, sort by newest/most viewed.
- Detail: YouTube embed (lazy, privacy-enhanced `youtube-nocookie.com`), title, date, duration, guest card(s), show notes (MDX), chapters/timestamps that seek the video, full transcript (collapsible), key takeaways, related episodes, share links.
- `PodcastEpisode`/`VideoObject` JSON-LD on each episode page.

### 5.3 Guests `/guests` and `/guests/[slug]`
- Directory of past guests: headshot, name, title, company, episode link(s).
- Profile page: bio, LinkedIn/website links, their episodes.

### 5.4 Be a Guest `/guest-application`
- Pitch to prospective guests: what the show is, interview format, time commitment, what they get.
- Application form: name, email, title, company, LinkedIn URL, bio, proposed topics, a concrete implementation story they'd share, availability/timezone, how they heard about the show.
- On submit: store in DB, confirmation email to applicant, notification to Ayan.

### 5.5 About `/about`
- Mission and origin story; what makes the show different.
- Host section: Ayan's bio and photo. **Ask Ayan to confirm exactly what to say about his employer and background before publishing.**
- What guests can expect; topics covered; interview style.
- Light stats (episodes, guests, industries) — only show once numbers are meaningful.

### 5.6 Contact `/contact`
- Form: name, email, subject (General, Guest Application, Sponsorship, Press, Other), message.
- Direct email and social links.
- FAQ: being a guest, recording process (remote via Riverside), release timeline.

### 5.7 Admin `/admin` (authenticated)
Guest management & scheduling system:
- **Roles:** Admin (full), Editor (content + applications), Viewer (read-only). Enforce with Supabase RLS, not just UI.
- **Pipeline (Kanban + table views):** `Prospect → Invited → Applied → Shortlisted → Scheduled → Recorded → Editing → Published` (+ `Declined`, `On hold`).
- **Contacts:** guest records with notes, tags, source (network / LinkedIn / referral), referral-from link, history of status changes.
- **Bulk import:** CSV import for the existing pipeline (~30 contacts from Ayan's network). Build this early.
- **Outreach:** reusable email templates with merge fields; send from the app; log sends. Every outbound email requires an explicit click by Ayan — no automatic blasts.
- **Scheduling:** propose slots, guest self-books, calendar invite with Riverside link, timezone conversion, iCal export.
- **Reminders:** automated reminders to guests (e.g. 48h and 2h before recording) and to Ayan for stalled pipeline items.
- **Episode linking:** connect a guest record to its published YouTube episode.
- **Export:** CSV/Excel export of any view.
- **Dashboard:** counts by stage, upcoming recordings, YouTube views/subscribers trend.

## 6. YouTube integration

- Sync runs at build and ISR (about hourly) from YouTube’s public channel feed, or the Data API when `YOUTUBE_API_KEY` is set. Fields: video ID, title, description, publish date, thumbnails, and duration plus view count when the API key is present.
- Store in `episodes` table; enrichment (slug, guests, tags, show notes MDX, transcript, chapters) is added in admin or `/content`.
- Unpublished/unlisted videos never appear publicly.
- Cache aggressively (ISR, revalidate ~1h) and respect API quota.
- Use a lite YouTube embed (thumbnail + click-to-load) for performance.

## 8. Non-functional requirements

- **Performance:** Lighthouse ≥ 95 on Performance, Accessibility, Best Practices, SEO for public pages; pass Core Web Vitals. WebP/AVIF images via `next/image`, lazy loading.
- **SEO:** unique titles/descriptions, Open Graph + Twitter cards (auto-generated OG images per episode), sitemap.xml, robots.txt, canonical URLs, JSON-LD.
- **Security:** HTTPS only, server-side validation (zod) on every form, rate limiting on public endpoints, bot protection, RLS on every table, secrets only in env vars, protected admin routes.
- **Privacy:** GDPR-style handling for guest data — consent checkbox on forms, privacy page, ability to delete a guest record on request.
- **Backups:** Supabase daily backups enabled.

## 10. Working rules for Grokbot

**Always**
- Read this file at the start of each session; keep a `PROGRESS.md` with what's done, what's next, and open decisions.
- Work on feature branches with small, well-described commits (Conventional Commits).
- Write or update tests with every feature; keep `npm run lint && npm run typecheck && npm test` green.

**Ask Ayan first before**
- Choosing the final palette, fonts, logo treatment, or homepage copy.
- Publishing anything about Ayan personally or his employer.
- Adding any paid service or plan upgrade.
- Deploying to the production domain or changing DNS.
- Sending any real email to a real guest, or importing real contact data into a hosted environment.

**Never**
- Commit secrets, API keys, or real guest PII to the repo or test fixtures.
- Add audio hosting, RSS feeds, or a custom audio player.
- Introduce playful/cluttered design patterns or more than 3 brand colors.
- Auto-send outreach emails without an explicit human click.
- Use fake testimonials, fake guest names, or fabricated stats on public pages (use clearly marked placeholders in dev only).
